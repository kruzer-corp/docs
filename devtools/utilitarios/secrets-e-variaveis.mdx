---
title: "Secrets e Variáveis no Código"
description: "Leia valores por tenant com Vars.get e Secrets.get e envie credenciais pelo conector REST sem passá-las pelo código"
icon: "code"
---

O `@kruzer/idk` lê os valores cadastrados em [Secrets e Variáveis](/devtools/plataforma/secrets-e-variaveis) pelo nome. O tenant vem sempre da execução: você não passa o tenant como parâmetro, e o mesmo código recebe o valor de homologação ou de produção conforme o tenant que está executando.

<Note>
  Requer `@kruzer/idk` **1.5.0 ou superior** e um runtime com suporte. Veja [onde funciona](/devtools/plataforma/secrets-e-variaveis#onde-funciona).
</Note>

## Importação

```typescript
import { Secrets, Vars } from '@kruzer/idk';
```

---

## Qual forma usar

| Situação | Use | Por quê |
|----------|-----|---------|
| Credencial que vai para um sistema externo por um conector | `{{secret:NOME}}` ou `Secrets.ref('NOME')` na chamada do conector | O conector troca pelo valor no servidor. O valor não passa pelo seu código |
| Configuração não sensível (URL, código de filial, limite) | `Vars.get('NOME')` | Devolve o valor. Recusa valores sensíveis |
| O código precisa do valor em si (ex.: assinar uma mensagem com uma chave HMAC) | `Secrets.get('NOME')` | Devolve qualquer valor, sensível ou não. **Nunca** faça `console.log` dele |

<Tip>
  Prefira `{{secret:NOME}}` sempre que o valor só precisa chegar ao sistema externo. É a forma em que o valor sensível fica mais protegido.
</Tip>

---

## Métodos

### Vars.get()

Devolve o valor de uma variável (não sensível) do tenant da execução.

```typescript
Vars.get(name: string): Promise<string>
```

```typescript
const filial = await Vars.get('CODIGO_FILIAL');
```

Se o nome for de um valor sensível, lança `SecretIsSensitiveError`. Use `Secrets.get` ou `{{secret:NOME}}` nesse caso.

### Secrets.get()

Devolve o valor, sensível ou não, do tenant da execução.

```typescript
Secrets.get(name: string): Promise<string>
```

```typescript
const chaveHmac = await Secrets.get('CHAVE_HMAC');
```

<Warning>
  O valor devolvido por `Secrets.get` é o valor em claro. Os loggers do idk o redigem (veja a seção Redação nos logs, abaixo), mas um `console.log` direto **não** é redigido.
</Warning>

### Secrets.ref()

Devolve a referência `{{secret:NOME}}` para usar dentro de uma chamada de conector. É síncrono e não busca o valor: só valida o nome e monta o texto.

```typescript
Secrets.ref(name: string): string
```

```typescript
Secrets.ref('API_TOKEN'); // '{{secret:API_TOKEN}}'
```

### Nomes

Os três métodos aceitam só nomes no formato do painel: letras maiúsculas, números e `_`, começando por letra, com até 64 caracteres. Um nome fora desse formato lança `TypeError` antes de qualquer busca.

## Cache e propagação

- O idk guarda cada valor em memória por tenant e nome. Uma alteração no painel vale em **até 60 segundos**, sem deploy.
- O tempo do cache é definido por `KRZ_SECRETS_CACHE_TTL`, em milissegundos (padrão `60000`).
- Chamadas simultâneas ao mesmo nome fazem uma só busca.

### Se a plataforma ficar indisponível

| O que aconteceu | Comportamento |
|-----------------|---------------|
| Falha de rede, erro 5xx ou 429 ao buscar, com um valor já em cache | Usa o último valor conhecido por até 15 minutos além do tempo de cache e escreve um aviso no log |
| Mesma falha, sem valor em cache (ou passado esse prazo) | Lança `SecretsUnavailableError` |
| Outra recusa (ex.: 403) | Lança `SecretsUnavailableError`, sem usar o cache |

## Redação nos logs

Os valores sensíveis entregues por `Secrets.get` saem como `[REDACTED]` nos loggers do idk (`KrzLogger` e `logger`):

- em qualquer parte da mensagem, inclusive dentro de objetos;
- na forma crua e na forma escapada do JSON.

```typescript
const logger = new KrzLogger('info', 'minha-automacao');
const chaveHmac = await Secrets.get('CHAVE_HMAC');

logger.info('configuração', { chaveHmac }); // {"chaveHmac":"[REDACTED]"}
console.log(chaveHmac);                     // sai em claro: não faça isso
```

Limites da redação:

- valores com menos de 4 caracteres não são redigidos, porque a troca apagaria texto comum;
- só os valores entregues por `Secrets.get` entram na redação. Variáveis não sensíveis não são redigidas;
- `console.log`, `console.error` e outras saídas diretas não passam pela redação.

## `{{secret:NOME}}` no RestDataSource

Coloque `{{secret:NOME}}` em qualquer texto da chamada do [`RestDataSource`](/devtools/integracoes/rest-api). O conector REST troca a referência pelo valor no servidor, antes de chamar o sistema externo. O valor não passa pelo código da automação.

A troca vale em qualquer string de:

- `body`;
- `headers`;
- `params` (query);
- `urlParams` (path).

A referência pode estar sozinha ou dentro de um texto maior, como `Bearer {{secret:API_TOKEN}}`. `Secrets.ref('NOME')` gera a mesma referência.

<CodeGroup>
```typescript Corpo JSON-RPC
import { randomUUID } from 'crypto';
import { RestDataSource } from '@kruzer/idk';

// ex.: um gateway de pagamentos em JSON-RPC, que recebe usuário e senha no corpo
const pagamentos = new RestDataSource('meu-gateway-pagamento');

const resposta = await pagamentos.request('consulta_saldo', {
  body: {
    jsonrpc: '2.0',
    method: 'consulta_saldo',
    id: randomUUID(),
    params: [
      'pt',
      '{{secret:MEU_GATEWAY_PAGAMENTO_USUARIO}}',
      '{{secret:MEU_GATEWAY_PAGAMENTO_SENHA}}'
    ]
  }
});
```

```typescript Cabeçalho
import { RestDataSource } from '@kruzer/idk';

const api = new RestDataSource('api-externa');

const pedidos = await api.request('listar-pedidos', {
  headers: {
    Authorization: 'Bearer {{secret:API_TOKEN}}'
  }
});
```

```typescript Com Secrets.ref
import { RestDataSource, Secrets } from '@kruzer/idk';

const api = new RestDataSource('api-externa');

const pedidos = await api.request('listar-pedidos', {
  headers: {
    Authorization: `Bearer ${Secrets.ref('API_TOKEN')}`
  }
});
```
</CodeGroup>

<Note>
  A referência só é reconhecida com o nome no formato válido (maiúsculas, números e `_`). Algo como `{{secret:api_token}}` não é trocado e chega ao sistema externo como texto literal.
</Note>

### Regras

<AccordionGroup>
  <Accordion title="Valor sensível só no corpo ou em cabeçalho">
    Um valor **sensível** em `params` (query) ou `urlParams` (path) faz o conector responder **400**, porque ficaria registrado nos logs de acesso do sistema externo. Variáveis não sensíveis podem ir na query e no path.
  </Accordion>

  <Accordion title="Pré-condições da chamada">
    Quando a chamada usa `{{secret:NOME}}`, o conector exige:

    - o **token de execução**, que o idk 1.5.0 ou superior envia automaticamente quando a automação roda num runtime da plataforma;
    - o **tenant da execução**, que o `RestDataSource` envia automaticamente;
    - nenhum `baseURL` nas opções da chamada: o destino é sempre o endereço da credencial do conector;
    - `responseType` ausente, `json` ou `text`, porque a resposta precisa ser redigida;
    - nenhum cabeçalho `Host`, `X-Forwarded-Host` ou `Forwarded`.

    Se alguma faltar, o conector responde **400** sem chamar o sistema externo.
  </Accordion>

  <Accordion title="Destino travado">
    Com `{{secret:NOME}}`, a chamada vai sempre para o endereço da credencial do conector:

    - redirecionamentos (3xx) não são seguidos;
    - opções que mudariam o destino, como `proxy`, são ignoradas;
    - um path que sairia do endereço da credencial responde **400**.
  </Accordion>

  <Accordion title="API que responde na raiz">
    Se a API responde na raiz do endereço (sem path), cadastre a **URN** do endpoint no conector como `.` (ponto). O conector não aceita URN vazia.
  </Accordion>

  <Accordion title="Sem placeholder, nada muda">
    Chamadas sem `{{secret:NOME}}` seguem exatamente como antes, inclusive na forma da resposta.
  </Accordion>
</AccordionGroup>

### Redação na resposta

O sistema externo pode devolver o que recebeu. Por isso, o conector troca por `[REDACTED]` todo valor sensível usado na chamada, na resposta e na mensagem de erro, nas formas:

- crua;
- escapada no JSON;
- codificada na URL.

Se um valor sensível for usado em `auth` (Basic), o `base64(usuario:senha)` montado pelo conector também é redigido.

Limites:

- valores sensíveis com menos de 4 caracteres (como um CVV ou um PIN curto) não são redigidos, porque a troca apagaria texto comum da resposta;
- outras codificações feitas pelo sistema externo (base64 só do valor, entidades HTML, trechos parciais) não são reconhecidas.

Quando a chamada usa `{{secret:NOME}}`, o campo `config` da resposta vem reduzido a `method`, `baseURL` (sem usuário e senha) e `url`. Sem placeholder, `config` continua completo, como antes.

### Erros do conector

Quando a referência não pode ser resolvida, o conector responde com um destes status e **não** chama o sistema externo:

| Status | Quando |
|--------|--------|
| 400 | Pré-condição não atendida, nome inexistente no tenant, ou valor sensível na query ou no path |
| 403 | O token de execução foi recusado |
| 429 | Limite de resolução de valores excedido |
| 502 | A plataforma não conseguiu resolver os valores naquele momento |

Na automação, o erro chega como exceção da chamada. A mensagem fica em `error.response.data.message`:

```typescript
try {
  await pagamentos.request('consulta_saldo', { body });
} catch (error) {
  const status = error.response?.status;              // 400, 403, 429 ou 502
  const mensagem = error.response?.data?.message;     // ex.: 'secrets nao encontrados ou negados: MEU_GATEWAY_PAGAMENTO_SENHA'
  throw new Error(`falha ao chamar o gateway (${status}): ${mensagem}`);
}
```

## Erros

Os erros do idk são exportados pelo pacote:

```typescript
import { SecretIsSensitiveError, SecretNotFoundError, SecretsUnavailableError } from '@kruzer/idk';
```

| Erro | Lançado por | Quando |
|------|-------------|--------|
| `SecretNotFoundError` | `Vars.get`, `Secrets.get` | O nome não existe no tenant da execução. Localmente, também quando o valor é sensível (veja abaixo) |
| `SecretIsSensitiveError` | `Vars.get` | O valor é sensível |
| `SecretsUnavailableError` | `Vars.get`, `Secrets.get` | Não foi possível buscar o valor e não há valor em cache utilizável, ou não há execução nem login para identificar o tenant |
| `TypeError` | `Vars.get`, `Secrets.get`, `Secrets.ref` | Nome fora do formato |

```typescript
try {
  const limite = await Vars.get('LIMITE_LOTE');
} catch (error) {
  if (error instanceof SecretNotFoundError) {
    // cadastre LIMITE_LOTE no tenant em Integração → Secrets e variáveis
  }
  throw error;
}
```

## Testando localmente

Ao rodar com a [CLI](/devtools/cli) (`krz login` e `krz select tenant`), o idk usa o seu login e o tenant selecionado:

- **Variáveis não sensíveis:** `Vars.get` e `Secrets.get` devolvem o valor cadastrado no tenant.
- **Valores sensíveis:** não são entregues para login de usuário. `Secrets.get` lança `SecretNotFoundError`. Para testar, defina o valor no seu ambiente como `KRZ_SECRET_<NOME>`:

```bash
export KRZ_SECRET_CHAVE_HMAC='valor-de-teste'
```

- **`{{secret:NOME}}`:** sem token de execução, o conector responde **400**. Teste chamadas com referência em um trigger.

<Note>
  `KRZ_SECRET_<NOME>` só é lido fora dos runtimes. Quando a automação roda na plataforma, o valor vem sempre do painel.
</Note>

## Exemplo completo

Uma automação que usa as três formas:

```typescript
import { randomUUID } from 'crypto';
import { KrzLogger, RestDataSource, Secrets, Vars } from '@kruzer/idk';

export default async function run(input: { [key: string]: unknown }) {
  const logger = new KrzLogger('info', 'exemplo-secrets');
  const numeroCartao = String(input.numeroCartao);

  const filial = await Vars.get('CODIGO_FILIAL');      // não sensível
  const chaveHmac = await Secrets.get('CHAVE_HMAC');   // sensível: redigida no logger
  logger.info('valores', { filial, chaveHmac });       // chaveHmac sai [REDACTED]

  // usuário e senha vão para o gateway sem passar pelo código
  const resposta = await new RestDataSource('meu-gateway-pagamento').request('consulta_saldo', {
    body: {
      jsonrpc: '2.0',
      method: 'consulta_saldo',
      id: randomUUID(),
      params: [
        'pt',
        randomUUID(),
        '{{secret:MEU_GATEWAY_PAGAMENTO_USUARIO}}',
        '{{secret:MEU_GATEWAY_PAGAMENTO_SENHA}}',
        numeroCartao
      ]
    }
  });

  // APIs JSON-RPC podem responder HTTP 200 com `error` no corpo: leia o corpo
  if (resposta.data?.error) throw new Error(resposta.data.error.message);
  return resposta.data?.result;
}
```

Cadastre no tenant, em **Integração → Secrets e variáveis**:

| Nome | Tipo |
|------|------|
| `CODIGO_FILIAL` | Variável |
| `CHAVE_HMAC` | Sensível |
| `MEU_GATEWAY_PAGAMENTO_USUARIO` | Sensível |
| `MEU_GATEWAY_PAGAMENTO_SENHA` | Sensível |

## Solução de problemas

| Sintoma | Causa provável | O que fazer |
|---------|----------------|-------------|
| `secrets nao encontrados ou negados: NOME` | O nome não existe no tenant que executou, ou foi digitado diferente | Confira o nome exato (maiúsculas) e o tenant em **Integração → Secrets e variáveis** |
| 400 com `{{secret:}} exige token de execucao` | idk anterior a 1.5.0, ou runtime ainda sem suporte (hoje, os endpoints do API Gateway) | Atualize o `@kruzer/idk` e confira [onde funciona](/devtools/plataforma/secrets-e-variaveis#onde-funciona) |
| 400 com `valor sensivel nao pode ir em query ou path` | Valor sensível em `params` ou `urlParams` | Envie no corpo ou em um cabeçalho |
| 403 logo depois de conceder uma permissão | A permissão nova ainda não foi aplicada | Saia e entre de novo no painel. Para conta de serviço, salve a conta outra vez no IAM |
| 429 | Muitas resoluções em pouco tempo | Tente de novo após um intervalo |
| 502, ou `SecretsUnavailableError` | A plataforma não conseguiu resolver o valor naquele momento | Tente de novo. Se persistir, acione o suporte |
| `SecretIsSensitiveError` em `Vars.get` | O valor é sensível | Use `{{secret:NOME}}` na chamada do conector, ou `Secrets.get` |
| O sistema externo recebeu o texto `{{secret:...}}` literal | Nome fora do formato (ex.: minúsculas), então a referência não foi reconhecida | Use o nome em maiúsculas, igual ao cadastrado |
